# KT6368A 蓝牙芯片开发参考手册
本文档基于 KT6368A V2.0 官方手册整理，聚焦 BLE 透传场景下的核心信息、指令规范与开发流程，可直接用于驱动开发与问题排查。

## 一、芯片概述
### 1.1 基本定位
KT6368A 是清月电子推出的**蓝牙 5.1 双模纯数据透传芯片**，采用 SOP8 超小封装，主打低成本、极简开发，通过串口 AT 指令配置，蓝牙连接后自动进入透传模式，无需开发蓝牙协议栈。
- 支持双模：BLE + 经典蓝牙 SPP，同一时间只能二选一使用
- 角色定位：**仅支持 BLE 从机（Server）模式**，只能被动等待连接，无法主动发起连接
- 核心价值：将串口数据原封不动转为蓝牙无线传输，等效为「无线串口线」

### 1.2 版本区别（硬件引脚完全兼容）
| 型号 | 模式 | 低功耗 | 工作电流 | 定位 |
|------|------|--------|----------|------|
| KT6368A | BLE + SPP 双模 | 不支持 | 开机15mA，稳定约6mA | 成本优先，全功能 |
| KT6328A | 单模 BLE | 支持 | 待机μA级 | 低功耗场景 |
| KT6268A | 单模 BLE | 支持 | 功耗更低 | 极致低功耗，成本略高 |

> 注意：`AT+CL`低功耗指令、`AT+UT`广播间隔指令**仅 KT6328A/KT6268A 支持**，KT6368A 发送无效。

### 1.3 核心特性
- 供电范围：2.2V ~ 3.4V，推荐 3.3V
- 串口：标准 TTL 电平，波特率可配置，默认 115200
- 工作温度：-40℃ ~ 80℃
- 传输距离：板载天线＞15米
- 单包最大透传：1024 字节，默认单包 20 字节

## 二、硬件参数与引脚说明
### 2.1 SOP8 引脚定义
| 引脚号 | 引脚名 | 类型 | 功能说明 |
|--------|--------|------|----------|
| 1 | VBAT | 电源 | 电源输入，2.2~3.4V，推荐3.3V |
| 2 | LED | 输出 | 连接状态脚：连接成功输出高电平，未连接为高阻态 |
| 3 | VSS | 电源 | 地 |
| 4 | BT_RF | 射频 | 蓝牙天线引脚 |
| 5 | OSCI | 模拟 | 晶振输入 |
| 6 | OSCO | 模拟 | 晶振输出 |
| 7 | RX | 输入 | 串口接收，接外部 MCU 的 TX |
| 8 | TX | 输出 | 串口发送，接外部 MCU 的 RX |

> 关键提示：7、8 脚同时为固件升级接口，硬件设计必须预留测试点，推荐按 1/7/8/3 引脚顺序排列。

### 2.2 核心电气参数
| 参数 | 数值 | 说明 |
|------|------|------|
| 推荐供电 | 3.3V | 最高不得超过 3.4V |
| 上电瞬间电流 | ~20mA | 持续约300ms |
| 稳定工作电流 | ~6mA | BLE 连接后持续工作 |
| 串口电平 | 3.3V TTL | 与5V MCU连接时，RX/TX需串100Ω~1KΩ电阻 |

### 2.3 外设要求
1. **晶振**：24MHz，频率偏差 ≤ ±10ppm，负载电容 CL 推荐 12pF
2. **天线**：可直接焊 2.4cm 导线作为天线；设计时天线四周需包地、隔空，避免金属与绿油遮挡

### 2.4 串口通信默认参数
- 波特率：115200
- 数据位：8
- 停止位：1
- 校验位：无
- 流控：无

## 三、AT 指令集（核心）
### 3.1 指令通用规则
1. **格式要求**：所有指令必须以 `AT+` 开头，以 `\r\n`（0x0D 0x0A）结尾，否则不识别且会被当成透传数据发出
2. **记忆特性**：所有配置指令均为记忆型，设置一次芯片永久保存，下次上电自动生效
3. **生效条件**：多数配置修改后需软复位或重新上电生效
4. **失效场景**：蓝牙连接成功后，芯片自动进入透传模式，所有 AT 指令失效，均被当作数据透传
5. **返回格式**：查询指令返回格式为 `Qn+xx`，错误返回格式为 `ER+x`

### 3.2 系统控制指令
| 指令 | 功能 | 说明 | 示例 |
|------|------|------|------|
| `AT+CZ\r\n` | 芯片软复位 | 配置修改后执行，使参数生效 | `AT+CZ\r\n` |
| `AT+CW\r\n` | 恢复出厂设置 | 清除所有用户配置，回到默认状态 | `AT+CW\r\n` |
| `AT+CTxx\r\n` | 设置串口波特率 | 设置后需复位生效，xx为波特率编码 | `AT+CT05\r\n` = 115200（默认） |
| `AT+CR00\r\n` | 关闭上电回传信息 | 关闭后上电不主动输出版本日志 | `AT+CR00\r\n` |
| `AT+CR01\r\n` | 开启上电回传信息 | 默认开启 | `AT+CR01\r\n` |

#### 波特率编码对照表
| 编码 | 波特率 | 编码 | 波特率 |
|------|--------|------|--------|
| 01 | 9600 | 07 | 512000 |
| 02 | 19200 | 08 | 230400 |
| 03 | 38400 | 09 | 460800 |
| 04 | 57600 | 10 | 1000000 |
| 05 | 115200（默认） | 11 | 31250 |
| 06 | 256000 | 12 | 2400 |

### 3.3 蓝牙配置指令
| 指令 | 功能 | 说明 | 示例 |
|------|------|------|------|
| `AT+BMxxx\r\n` | 设置 BLE 设备名称 | 最长30字节，默认名 `KT6368A-BLE`；设置后需复位生效 | `AT+BMWATCH_BLE\r\n` |
| `AT+BNxxxxxxxxxxxx\r\n` | 设置 BLE MAC 地址 | 6字节12位十六进制；SPP地址自动在最高字节+1 | `AT+BN112233445566\r\n` |
| `AT+BDxxx\r\n` | 设置 SPP 设备名称 | 默认名 `KT6368A-SPP` | `AT+BDSPP_BOX\r\n` |

### 3.4 功能使能指令
| 指令 | 功能 | 说明 | 示例 |
|------|------|------|------|
| `AT+B401\r\n` | 开启 BLE 功能 | 设置后需重新上电生效；默认开启 | `AT+B401\r\n` |
| `AT+B400\r\n` | 关闭 BLE 功能 | 关闭后无法搜索到BLE设备 | `AT+B400\r\n` |
| `AT+B501\r\n` | 开启 SPP 功能 | 设置后需重新上电生效；默认开启 | `AT+B501\r\n` |
| `AT+B500\r\n` | 关闭 SPP 功能 | 仅使用BLE时建议关闭，减少干扰 | `AT+B500\r\n` |

### 3.5 查询指令
| 指令 | 功能 | 返回示例 | 说明 |
|------|------|----------|------|
| `AT+QT\r\n` | 查询当前波特率 | `QT+05` | 返回对应波特率编码 |
| `AT+TM\r\n` | 查询 BLE 设备名称 | `TM+WATCH_BLE` | 返回当前BLE名称 |
| `AT+TN\r\n` | 查询 BLE MAC 地址 | `TN+112233445566` | 返回12位十六进制地址 |
| `AT+TD\r\n` | 查询 SPP 设备名称 | `TD+SPP_BOX` | 返回当前SPP名称 |
| `AT+T4\r\n` | 查询 BLE 功能状态 | `T4+01` | 01=开启，00=关闭 |
| `AT+T5\r\n` | 查询 SPP 功能状态 | `T5+00` | 01=开启，00=关闭 |

### 3.6 错误码说明
| 返回值 | 含义 |
|--------|------|
| `ER+1` | 接收的数据帧格式错误 |
| `ER+2` | 指令不存在，无此功能 |
| `ER+3` | 指令缺少 `\r\n` 结尾 |
| `ER+4` | 参数超范围或指令格式错误 |
| `ER+7` | BLE连接状态下，手机/主机未开启 Notify，无法下发数据 |

## 四、BLE 透传机制
### 4.1 主从角色
- **从机（Server）**：KT6368A 固定为从机，上电后广播设备信息，等待连接；连接后可通过 Notify 主动发数据
- **主机（Client）**：由 ESP32/手机等扮演，主动扫描、发起连接；连接后可通过 Write 发数据，通过 Notify 收数据
- 两个从机之间无法直接通信

### 4.2 GATT 服务与 UUID
KT6368A 透传功能基于固定的 GATT 结构，UUID 不可修改：
| 层级 | UUID | 功能说明 |
|------|------|----------|
| 主服务（Service） | `FFF0` | 串口透传专用服务，所有透传功能均在此服务下 |
| 特征1（Characteristic） | `FFF1` | **推荐使用**，支持「主机写数据 Write」+「从机主动通知 Notify」，可完成双向透传 |
| 特征2（Characteristic） | `FFF2` | 支持「主机读数据 Read」+「从机主动通知 Notify」 |
| 特征3（Characteristic） | `FFF3` | 仅支持「主机写数据 Write」 |

### 4.3 透传工作原理
蓝牙连接成功后，芯片自动进入透传模式，数据双向原封不动转发：
1. **MCU → KT6368A → 主机**：MCU 串口发出的所有数据（非标准AT指令），芯片自动通过 BLE 的 Notify 推送给主机
2. **主机 → KT6368A → MCU**：主机通过 Write 发送的所有数据，芯片直接从串口原样输出给 MCU
3. 芯片不解析、不修改、不加工任何透传数据，完全等效于无线串口线

### 4.4 数据收发规则
- 默认单包最大 20 字节，超过会自动分包；可通过协商 MTU 提升单包长度，最大支持 1024 字节
- 数据格式完全由用户自定义，支持字符串、二进制等任意格式
- 主机端必须开启 `FFF1` 特征的 Notify 权限，否则收不到从机发送的数据

## 五、完整开发配置流程
### 5.1 首次上电配置（仅需执行1次）
配置前确保蓝牙未连接，串口参数 115200 8N1，按顺序发送以下指令，每条间隔 300ms：
```
AT+B500\r\n      // 关闭SPP，仅使用BLE
AT+BMWATCH_BLE\r\n  // 设置BLE设备名称，自定义
AT+CR00\r\n      // 关闭上电自动回传，避免干扰
AT+CZ\r\n        // 软复位，配置生效
```
复位后芯片以新名称开始广播，配置永久保存，后续上电无需重复设置。

### 5.2 STM32 从机端驱动要点
1. 硬件连接：KT6368A 的 TX 接 STM32 串口 RX，RX 接 STM32 串口 TX，交叉连接
2. 上电时序：给模块供电后，延时 200ms 再发送指令
3. 状态判断：读取 2 脚电平，高电平=连接成功，低电平=未连接
4. 数据发送：连接成功后，直接通过串口发送数据即可，无需额外协议
5. 数据接收：开启串口接收中断，直接读取收到的字节即可

### 5.3 ESP32 主机端对接要点
1. 开发流程：扫描设备 → 按名称/MAC过滤 → 发起连接 → 发现 `FFF0` 服务 → 找到 `FFF1` 特征 → **开启 Notify** → 双向收发
2. 必须步骤：连接后必须注册并开启 `FFF1` 特征的 Notify 回调，否则无法接收手表端数据
3. 数据发送：调用 `writeValue` 接口向 `FFF1` 特征写入数据
4. 异常处理：监听断开回调，断开后自动重启扫描重连

## 六、关键注意事项与常见问题
### 6.1 开发必知禁忌
1. 供电严禁超过 3.4V，推荐稳定 3.3V
2. AT 指令必须加 `\r\n` 结尾，否则不识别
3. 蓝牙连接后 AT 指令全部失效，所有数据均透传
4. KT6368A 不支持低功耗指令和广播间隔指令，仅KT6328A支持
5. 晶振必须加匹配负载电容，否则频偏过大导致搜不到设备

### 6.2 常见问题排查
| 现象 | 常见原因 |
|------|----------|
| 搜不到蓝牙设备 | 1. 供电异常；2. 晶振未焊负载电容；3. BLE功能被关闭；4. 天线未接 |
| 收不到从机发的数据 | 1. 主机未开启 Notify；2. 蓝牙未连接成功；3. 串口TX/RX接反 |
| AT 指令不生效 | 1. 未加 `\r\n` 结尾；2. 蓝牙已连接，进入透传模式；3. 波特率不匹配 |
| 修改名称后还是显示旧名称 | 1. 芯片未复位；2. 主机端蓝牙缓存旧名称，需重启蓝牙重新扫描 |
| 数据乱码 | 1. 两边波特率不一致；2. 电平不匹配；3. 共地不良 |
| 串口收到多余 FF 数据 | 模块进入低功耗模式，IO 为高阻态；需外接上下拉电阻或关闭低功耗 |
